The testing flavor intentionally defaults to an invalid API host. For an Android emulator, use `10.0.2.2` to reach the API on the development host; `127.0.0.1` means the emulator itself and works only when `adb reverse tcp:4000 tcp:4000` is active. A physical phone must use a development host LAN address reachable from that phone (or an HTTPS staging API). Rebuild it for this local audit with:

    cd android_app
    .\gradlew.bat "-PtestingApiBaseUrl=http://10.0.2.2:4000/api/v1/" :app:testEnvTestingDebugUnitTest :app:lintEnvTestingDebug :app:connectedEnvTestingDebugAndroidTest :app:assembleEnvTestingDebug

## Fixes made during this audit

- Corrected Android authentication cancellation and stale-result handling; a late request can no longer finish a reset or a newer login flow.
- Made Household refresh re-run after an in-flight refresh and showed queued pickup requests so a user cannot silently queue competing partner choices.
- Kept Recycler submission dialogs open through errors and blocked duplicate submits while a request is in flight.
- Reconciled the Recycler authorization status with the live session account so an already-verified Recycler starts in the marketplace; verification screens now navigate into operations once the refreshed profile is verified. Corrected the verified demo preview fixture to open the marketplace instead of showing a success/approval screen that contradicted its own verified account. Device checks exercised the direct landing and Market/Orders/Market tab flow on both small and normal emulator configurations; live verified-account cold login remains unverified.
- Made session rotation, payment state changes and source-listing allocation conditional/atomic; verified matching retries and concurrent requests against Mongo.
- Preserved REJECTED results when the same sync operation is retried.
- Matched Mongo optional-null fields correctly for refresh tokens and QR scans.
- Fixed boolean environment parsing for the literal false value.
- Made the Admin console respect server-issued permissions and start on the first section the account can use.
- Prevented a previous Household listing result left in the shared ViewModel from immediately navigating away from a newly opened listing draft; an instrumentation regression test verified that stale results are ignored while a new result still closes the form.
- Reduced the Household listing form’s fixed keyboard-state content: while the IME is open, the address field uses a compact placeholder and helper, and the missing-fields paragraph is hidden so the form can retain more viewport height. The current build was reinstalled and the 360×640 dp, 130% font address-entry flow was manually retested with ADB; the prompt and submit button remained visible with the keyboard open. The final Android regression run passed: 125 unit tests and 27 instrumentation tests on each API 24 and API 37 emulator.

## Risks and unverified boundaries

- One complete Household → Collector → Recycler transaction chain was run live through the isolated API/database, but not end-to-end through all role UIs. Admin was audited separately for permissions, exports, price scope, and review denial.
- Sync change reads and dataset exports still need large-volume profiling and bounded/paginated behavior review. The current audit used a small disposable database; it does not establish production-scale performance.
- Full airplane-mode operation, actual listing enqueue, process-death persistence, replay after reconnect, forced expired-token refresh and upload interruption need further fault-injection. An initial apparent offline submit was actually online through ADB reverse and was marked synced. The corrected attempt produced no local mutation or server request, but the physical tap/handler could not be established; the Compose regression test now covers the stale-notice navigation race, not the complete outbox flow. API-unreachable login was checked by removing/restoring the reverse route; this does not cover all offline states.
- SMS/FCM, external payment rails, Gemini, private storage, physical QR/camera/GPS, release installation and deployment have no live provider/hardware evidence.
- The supplied PM2 log excerpt shows requests to common web-login paths returning 404 in 0–1 ms. No source IP or actor is present in the excerpt, so it does not prove who sent them or whether they were automated. The excerpt shows no successful page response.
